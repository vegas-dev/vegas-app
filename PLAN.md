# PLAN: VEGAS APP 60-Day Execution

Период: 19 марта 2026 - 18 мая 2026

## Цель
За 60 дней перевести проект из состояния "сильная инженерная база" в состояние "продукт с регулярной выручкой": стабилизировать core, упаковать для рынка и запустить продажи по модели Open Core + Pro + Support.

## Этап 1 (Недели 1-2): Стабилизация ядра и релиз 1.1.0

### Технические задачи (критический приоритет)
1. Исправить проверку метода AJAX в `BaseModule`:
- Файл: `app/modules/base-module.js`
- Проблема: некорректная проверка `if (!'method' in this._params.ajax)`.
- Результат: корректный fallback на `get`.

2. Исправить `fetch` credentials в `Ajax`:
- Файл: `app/utils/js/components/ajax.js`
- Проблема: используется `withCredentials` в `fetch`, должен использоваться `credentials`.
- Результат: корректная отправка cookie в `fetch`-режиме.

3. Убрать опасную очистку всего `localStorage` в `VGLawCookie`:
- Файл: `app/modules/vglawcookie/js/vglawcookie.js`
- Проблема: `localStorage.clear()` удаляет все данные сайта.
- Результат: удаляется только ключ согласия.

4. Исправить нейминг экспорта модуля `VGFiles`:
- Файл: `app/modules/vgfiles/index.js`
- Проблема: внутреннее имя переменной `VGSidebar`.
- Результат: консистентный экспорт `VGFiles`.

5. Добавить базовый security-hardening для HTML-вставок:
- Файлы: `base-module`, `vgformsender`, `vgtoast`, `vgrollup` (и другие места `innerHTML` при данных с сервера).
- Результат: санитизация/whitelist для входящего HTML из сети.

### Product/ops задачи
1. Привести `package.json` к publish-ready виду:
- Заполнить `repository.url`.
- Исправить `bugs.url` на актуальный репозиторий.
- Проверить `homepage`, keywords, description.

2. Выпустить релиз `1.1.0` с changelog "stability + security + packaging".

### Критерии завершения этапа
- `npm pack --dry-run` без замечаний по метаданным.
- Production-сборка проходит.
- Критические баги устранены.
- Релиз `1.1.0` опубликован.

## Этап 2 (Недели 3-5): Продуктовая упаковка

### Инженерия
1. Добавить автотесты:
- Smoke + e2e для модулей: `VGModal`, `VGSelect`, `VGFiles`, `VGFormSender`, `VGTabs`, `VGToast`.
- Минимум: happy-path + 1-2 негативных сценария на модуль.

2. Устранить технические долги сборки:
- Миграция Sass с `@import` на `@use/@forward`.
- Замена deprecated global built-ins (`type-of`, `mix`, `map-get`).

3. Разделить сборки:
- `core` (базовые модули).
- `full` (все модули).

### Документация
1. Сделать "Quick Start" (NPM/CDN, JS API, Data API).
2. Подготовить 8-10 живых рецептов:
- modal + formsender;
- select remote search;
- files upload + preview;
- tabs + ajax;
- sidebar/nav/dropdown комбинации.
3. Доделать документацию для `VGModal` (сейчас нет module README).

### Критерии завершения этапа
- Есть автотесты на ключевой функционал.
- Документация покрывает путь "установить -> интегрировать -> запустить".
- Сборки `core/full` доступны и описаны.

## Этап 3 (Недели 6-8): Монетизация и запуск продаж

### GTM и продажи
1. Запустить лендинг/сайт продукта:
- ценность;
- сравнение Free vs Pro;
- лицензирование;
- FAQ;
- контакт для Enterprise.

2. Запустить модель Open Core + Pro + Support:
- Free: core-компоненты, community support.
- Pro: расширенные компоненты и шаблоны.
- Enterprise: SLA, приоритетные фиксы, onboarding.

3. Подготовить `VGApp Pro v1`:
- 2-3 платных расширения (например):
  - Advanced Select (virtualization, async cache);
  - Upload Pro (chunk/resume);
  - Form Builder Lite.

4. Каналы привлечения:
- npm/GitHub;
- Habr/VC статьи с кейсами;
- Telegram/сообщества frontend;
- партнерство с веб-студиями и интеграторами.

### Критерии завершения этапа
- Опубликованы тарифы и лицензии.
- Запущен платежный путь/вход в продажу.
- Есть первые платящие клиенты.
