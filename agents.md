### Окружение
 - Проект, репозиторий, vegas-app является основным, фундаментальным. Тут идет разработка, редактирование проекта vgapp.
 - Проект, репозиторий, vegas-app-backend является демонстрационным, для тестирования и проверки работоспособности.
 - Оба проекта связаны между собой симлинками, но при этом имеют разные цели и функциональность.


### Свод правил:
1. Правила по changelog для проекта vegas-app:
   - Правило: при команде "записать в changelog" или "дополни changelog" записываем вкратце изменения в файл `D:\OSPanel\home\projects\vegas-app\CHANGELOG.md`, которые были сделаны с прошлой версии. Записываем так: Версия (смотри `package.json`), дата и построчно что было внесено, нужно как-то выделить новые фичи.
   - Смотрим только проект и репозиторий vegas-app, а не связанные.
   - Если версия в `package.json` не изменилась, нужно проверить, есть ли эта версия в `CHANGELOG.md`.
   - Если запись версии уже есть, дописывать изменения в существующую запись (как дополнение), а не создавать новый блок той же версии.
   - Если записи версии нет, создавать новый блок с версией из `package.json`, датой и списком изменений, запись добавляется сверху.
2. Все файлы должны иметь кодировку UTF-8.
3. Перед вёрсткой или изменением интерфейса демонстрационного проекта `vegas-app-backend` сначала изучать и переиспользовать возможности основного проекта `vegas-app` и установленной в демо-проекте версии npm-пакета `okaux`:
   - проверять публичные точки входа, документацию и исходники компонентов, токенов, тем и Data API; не дублировать уже существующие компоненты и системную логику локальным кодом без необходимости;
   - учитывать фактически установленную версию `okaux` из `vegas-app-backend/package-lock.json` и её публичный контракт, а не опираться на предположения о последней версии;
   - при совместном использовании тем оставлять единый источник состояния темы в `okaux` (`data-theme`, `data-ox-theme-*`, `okaux.theme`) и подключать переменные `vgapp` к тому же селектору через публичный SCSS-адаптер `vgapp/theme`.
4. Всю создаваемую и обновляемую документацию по проекту `vegas-app` хранить в репозитории `vegas-app-backend`, в каталоге `docs/vegas-app`:
   - к документации относятся дорожные карты, архитектурные решения, руководства, описание API и модулей, примеры интеграции и миграционные инструкции;
   - в репозитории `vegas-app` не создавать новые файлы проектной документации и не расширять существующие модульные README: соответствующий материал оформлять в `vegas-app-backend/docs/vegas-app`;
   - исключения: `CHANGELOG.md`, корневой `README.md`, служебные комментарии в коде и метаданные пакета; изменять их только в рамках их прямого назначения или по явной команде пользователя.
5. В начале каждого создаваемого или изменяемого файла `.js`, перед импортами и исполняемым кодом, добавлять краткую JSDoc-аннотацию:
   - `Описание` — назначение файла;
   - `Возможности` — его основные функции и поддерживаемые сценарии;
   - аннотация должна быть краткой, актуальной и обновляться вместе с изменением ответственности файла.
6. Для таблиц использовать публичный контракт VGApp: `.vg-table[data-vg-table]`. Классы `.table` и `.table-responsive` не использовать.
